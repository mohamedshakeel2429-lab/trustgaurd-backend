# ScamChain Android

ScamChain is a Kotlin + Jetpack Compose Android app backed by a FastAPI service. All analysis and chat replies come from a configured Groq model. There is no local rule-based or mock response fallback: if Groq is unavailable or not configured, the app reports that clearly.

## Run the backend

From `backend`, create a Python virtual environment, install `requirements.txt`, and copy `.env.example` to `.env`. Add fresh provider keys to that backend-only `.env`:

```dotenv
GROQ_API_KEY=your_new_groq_key
GROQ_ANALYSIS_MODEL=qwen/qwen3.8-27b
GROQ_CHAT_MODEL=qwen/qwen3.8-27b
SERPAPI_API_KEY=your_serpapi_key
```

Start the service with `uvicorn app.main:app --host 0.0.0.0 --port 8000`. `/health` shows whether Groq and SerpApi are configured without returning either key. The Android app never stores provider credentials.

## Run Android

Open this folder in Android Studio with JDK 17 and Android SDK Platform 36. Run the `app` configuration on an emulator. The default emulator backend is `http://10.0.2.2:8000/api/v1`. For a device or hosted backend, set `SCAMCHAIN_API_URL` or pass `-PscamchainApiUrl=https://your-host/api/v1` to Gradle. Debug permits cleartext HTTP for local development; release disables it.

## Firebase sign-in

Firebase is configured for Android package `com.scamchain.app`. Enable Email/Password under Authentication sign-in providers in Firebase Console. New accounts save the display name and email in Firebase Authentication; passwords are handled by Firebase Auth and are not stored by ScamChain in another database.

## App behavior

- **Analyze:** a user submits typed text or an explicitly approved screenshot to the Groq model. Typed email and long-number masking is on by default. Screenshot pixels are not masked.
- **Chat:** the assistant handles general questions as well as scam and digital-safety topics. It answers the specific question directly and uses SerpApi automatically for current information, website requests, and company scam or incident questions. Every answer is generated by Groq; failures are shown instead of replaced with a canned answer.
- **Web lookup:** relevant chat questions are sent to SerpApi, and returned Google result titles, snippets, and URLs are passed to Groq. Users see clickable sources when results are available. Analysis cross-check remains optional. This is search-result retrieval, not full-page scraping; snippets may omit context or be out of date.
- **Uncertainty:** a model can produce false positives (flag a legitimate message) and false negatives (miss a scam). A risk label is not proof. Verify important requests using contact details you independently trust.
- **Screen capture:** Android asks for consent each time. The image is previewed locally and sent only after the user chooses Analyze. Android may prevent capture of protected content.
- **Overlay/accessibility:** the floating shortcut only opens the app. Accessibility is optional and the included scaffold does not read active-window text or monitor activity.
- **Complaint handoff:** the app can prepare a summary and open the official cybercrime portal, but it does not file a complaint or claim government affiliation. For financial cyber fraud in India, the portal provides the 1930 helpline.

## API endpoints

- `GET /health`: backend and provider readiness (never returns keys).
- `POST /api/v1/analyze`: Groq text/image risk analysis and optional official-source SerpApi lookup.
- `POST /api/v1/chat`: versatile multi-turn Groq chat with optional SerpApi web search.
- `POST /api/v1/incidents`: currently returns a preparation reference only; it stores no case data and files nothing officially.

Backend requests are not logged by the API. Before public deployment, add authentication, rate limits, HTTPS, retention policy, and operational monitoring. Rotate the Groq key previously shared in chat before using this backend. Keep both provider keys out of source code, Android builds, and screenshots.

## Project layout

```text
app/src/main/java/ai/scamchain/mobile/
  accessibility/  opt-in AccessibilityService scaffold
  capture/        consent-based one-shot MediaProjection capture
  data/           Groq/SerpApi-backed API contracts and HTTP client
  overlay/        opt-in floating shortcut
  ui/             Compose dashboard, analysis, chat, privacy, and reporting flows
backend/app/       FastAPI routes, Groq calls, and SerpApi search
```
